## Component Inventory

All components are Dolibarr native PHP patterns. No new components are installed.

### 1. Tab Bar Extension

- **What:** 4th entry appended to the `$head[]` array before `dol_get_fiche_head()` call.
- **Tab key:** `deadletter`
- **Tab label lang key:** `WallboxDeadLetter` → displayed as "Fehlgeschlagen"
- **Tab URL:** `$_SERVER['PHP_SELF'].'?tab=deadletter'`
- **Position:** 4th (after rfid, index `$h=3`)
- **Pattern source:** admin.php lines 95–108 (verbatim pattern)

### 2. Dead-letter Table

- **Container:** `<div class="div-table-responsive">` wrapping `<table class="noborder centpercent">`
- **Header row:** `<tr class="liste_titre">`
- **Data rows:** `<tr class="oddeven">` (Dolibarr alternating stripe)
- **Columns (6):**

| # | Column Header (lang key) | Source Field | Output Treatment |
|---|--------------------------|--------------|-----------------|
| 1 | `WallboxDeadLetterCreated` → "Erstellt" | `created_at` | `htmlspecialchars()` |
| 2 | `WallboxID` → "Wallbox-ID" | `wallbox_id` | `htmlspecialchars()` |
| 3 | `kWh` → "kWh" | `total_kwh` | `number_format((float), 2)` |
| 4 | `Error` → "Fehler" | `error_msg` | `htmlspecialchars()` — truncate display to 80 chars with `...` if longer |
| 5 | `WallboxRetryCount` → "Versuche" | `retry_count` | `(int)` cast, plain output |
| 6 | `Action` → "Aktion" | — | Retry form (see below) |

- **No rfid_hash column** — rfid_hash is NEVER included in any print statement (SEC-01/02 pattern from Phase 6).
- **Error column truncation:** `htmlspecialchars(mb_substr($obj->error_msg ?? '', 0, 80), ENT_QUOTES, 'UTF-8').(mb_strlen($obj->error_msg ?? '') > 80 ? '...' : '')`

### 3. Status Badge

- **"ausstehend" (pending):** `<span style="color:orange">ausstehend</span>`
- **"erledigt" (resolved):** `<span style="color:green">erledigt</span>`
- Status badge appears in the "Versuche" column as a sub-line, OR may replace the Aktion column when `status='resolved'`.
- **Only pending entries are shown in the table** (query `WHERE status='pending'`). Resolved entries do not appear — the empty state handles the "all resolved" case.

### 4. "Wiederholen" Retry Button (per row)

Pattern replicates the `stop_session` form in admin.php lines 226–233 exactly:

```
<form method="POST" action="{PHP_SELF}?tab=deadletter" style="display:inline">
  <input type="hidden" name="token" value="{newToken()}">
  <input type="hidden" name="action" value="retry_dead_letter">
  <input type="hidden" name="dead_letter_id" value="{(int)$obj->id}">
  <input type="submit" class="button smallpaddingimp" value="Wiederholen">
</form>
```

- **One form per table row** — isolated POST, no batch retry in Phase 8.
- **`class="button smallpaddingimp"`** — matches the "Session beenden" button in Phase 6.
- **CSRF:** `newToken()` in every form — mandatory, matches Phase 6 requirement (T-06-12).
- **`dead_letter_id` type:** integer-only via `(int)$obj->id` cast in hidden field.

### 5. Empty State

- Rendered as a single `<tr class="oddeven">` spanning all 6 columns.
- `<td colspan="6">{langs->trans('WallboxNoDeadLetterEntries')}</td>`
- German copy: "Keine fehlgeschlagenen Übertragungen vorhanden."
- Shown when: (a) `/dead-letter/list` returns an empty array, (b) cURL returns HTTP 200 with `[]`.

### 6. HA Unreachable State

- Shown when cURL to `/dead-letter/list` fails (curl_error or non-200 HTTP).
- Replaces the table with a single error row:
  `<td colspan="6"><span style="color:red">HA-Addon nicht erreichbar: {htmlspecialchars($curl_error)}</span></td>`
- Does NOT abort page render — other tabs remain accessible.

### 7. Post-Retry Feedback (setEventMessages)

- **On success (HTTP 200 from `/session/retry`):**
  `setEventMessages($langs->trans('RetryDeadLetterSuccess'), null, 'mesgs')`
  German copy: "Übertragung erfolgreich wiederholt."
- **On failure (curl_error or non-200):**
  `setEventMessages($langs->trans('RetryDeadLetterFailed').': '.$err_detail, null, 'errors')`
  German copy prefix: "Wiederholen fehlgeschlagen: " + error detail.
- Pattern source: admin.php lines 68–77 (stop_session feedback — verbatim).

is deleted from the UI.

## Interaction Contract

### Page Load Sequence (tab=deadletter)

1. PHP enters `elseif ($tab == 'deadletter')` block.
2. Read `WALLBOXBILLING_HA_URL` via `getDolGlobalString()`.
3. If empty: render unconfigured message (same as Status tab unconfigured state).
4. cURL GET to `{HA_URL}/dead-letter/list` with `CURLOPT_TIMEOUT=4`, `CURLOPT_CONNECTTIMEOUT=4`.
5. On curl_error: render HA unreachable state in table.
6. On HTTP 200: JSON decode response array, render table rows.
7. If array empty: render empty state row.
8. If array non-empty: render one row per entry with Retry form.

### Retry Button Click Sequence

1. Admin clicks "Wiederholen" on a row.
2. Browser POSTs `action=retry_dead_letter` + `dead_letter_id={N}` + CSRF token.
3. PHP action handler (before HTML output): `checkToken()`, `GETPOST('dead_letter_id', 'int')`.
4. cURL POST JSON `{"dead_letter_id": N}` to `{HA_URL}/session/retry` with 4s timeouts.
5. HA Addon processes retry, returns HTTP 200 or error.
6. PHP calls `setEventMessages(...)`.
7. `header('Location: '.$_SERVER['PHP_SELF'].'?tab=deadletter'); exit;` — PRG redirect.
8. Page reloads: table re-fetches live data from `/dead-letter/list` — resolved entry no longer appears.

### State Transitions Visible in UI

| State | Trigger | Visual Result |
|-------|---------|---------------|
| Pending entry exists | Failed upload → dead_letter table | Row with "Wiederholen" button |
| Retry succeeded | Admin clicks Wiederholen → HA responds 200 | Entry disappears from table on reload; success banner |
| Retry failed | HA returns error | Entry remains in table with incremented Versuche; error banner |
| All entries resolved | All retried successfully | Empty state message shown |
| HA unreachable | cURL error on tab load | Error row in table, no action possible |

## Security Constraints (UI Layer)

These are UI-layer rules that the executor must enforce. They mirror Phase 6 threat model.

| Constraint | Rule | Pattern Source |
|------------|------|----------------|
| No rfid_hash in output | `grep "print.*rfid_hash" admin.php` must return 0 | Phase 6 SEC-01/02 |
| CSRF token on every POST | `newToken()` in every Retry form | Phase 6 T-06-12 |
| `checkToken()` in action handler | Before any cURL call in `retry_dead_letter` action | Phase 6 T-06-09 |
| XSS prevention on all output | `htmlspecialchars($var, ENT_QUOTES, 'UTF-8')` on every dynamic string | Phase 6 T-06-10 |
| `dead_letter_id` integer coercion | `GETPOST('dead_letter_id', 'int')` — reject 0 | Phase 6 T-06-09 (stop_session pattern) |
| cURL timeout | `CURLOPT_TIMEOUT=4` + `CURLOPT_CONNECTTIMEOUT=4` on both cURL calls | Phase 6 T-06-14 |
| No JSON with rfid_hash | `/dead-letter/list` response must not contain rfid_hash field; admin.php must not render it | RESEARCH.md Security section |
