## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → admin.php POST | Admin submits retry form — dead_letter_id crosses browser→server boundary |
| admin.php → HA-Addon cURL | PHP makes server-side cURL calls to HA-Addon on configured URL |
| HA-Addon → admin.php JSON | /dead-letter/list JSON response decoded and rendered as HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | dead_letter_id POST parameter | mitigate | `GETPOST('dead_letter_id', 'int')` integer coercion; `$dead_letter_id > 0` check before any cURL call — implemented in retry_dead_letter handler, Task 1 Change 2 |
| T-08-02 | Tampering | CSRF on retry form | mitigate | `checkToken()` in action handler + `newToken()` in each Retry form (per D-05) — both enforced in acceptance criteria |
| T-08-03 | Info Disclosure | rfid_hash in /dead-letter/list display | mitigate | PHP never accesses $entry['rfid_hash'] — HA endpoint excludes it from JSON response (Plan 08-02); acceptance criteria grep confirms 0 instances of `print.*rfid_hash` |
| T-08-04 | Tampering | XSS via error_msg from HA response | mitigate | `htmlspecialchars(mb_substr($err_raw, 0, 80), ENT_QUOTES, 'UTF-8')` applied to error_msg before print — per UI-SPEC §3 truncation pattern; acceptance criteria grep confirms presence |
| T-08-05 | Integrity | Double-retry on fast click | accept | POST→Redirect→GET pattern prevents double-submit on browser reload; concurrent clicks may create two HA requests, but HA-Addon uses dead_letter.status='resolved' guard (Plan 08-02) |
| T-08-06 | Elevation | SSRF via cURL URL | mitigate | Both cURL calls use `$ha_url = getDolGlobalString('WALLBOXBILLING_HA_URL', '')` — admin-configured value, not user input; same mitigation as existing stop_session cURL pattern |
</threat_model>
