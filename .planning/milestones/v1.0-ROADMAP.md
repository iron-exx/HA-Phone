# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-11
**Phases:** 1-5
**Total Plans:** 10

## Overview

Automatisierte, RFID-basierte Abrechnung von Wallbox-Ladevorgängen ohne manuellen Aufwand. Vollständige Integration von Home-Assistant-Addon (Alfen Eve Wallbox) und Dolibarr-ERP-Modul.

## Phases

### Phase 1: Foundation (HA Integration + Dolibarr Skeleton)

**Goal**: Establish technical foundation for both HA Addon and Dolibarr Module
**Depends on**: Nothing (first phase)
**Plans**: 2 plans

Plans:
- [x] 01-01-PLAN.md — HA Addon Foundation (Dockerfile, Websocket API, Hash Utility)
- [x] 01-02-PLAN.md — Dolibarr Module Skeleton (modWallboxbilling, SQL table, Permissions, Frontend pages)

**Details:**
- HA Addon on Alpine 3.23, Python 3.13
- Websocket API integration for Alfen Eve sensors (RFID tag, energy total, charging status)
- SHA-256 hash utility for RFID (SEC-02)
- Dolibarr module with proper descriptor, install/uninstall, SQL table creation (DB-03)
- 3 permissions: user (read), admin (read/write), billing (billing operations) (SEC-04)
- 4 frontend pages: setup, sessions, admin settings, about
- German language files for Dolibarr

### Phase 2: Session Tracking + User Management

**Goal**: HA Addon tracks charging sessions with RFID authentication; Dolibarr manages users with RFID-hash and pricing
**Depends on**: Phase 1 (need sensors and module)
**Plans**: 2 plans

Plans:
- [x] 02-01-PLAN.md — HA Addon Session Tracking (session_manager.py, SQLite, RFID Whitelist, Debouncing)
- [x] 02-02-PLAN.md — Dolibarr User Management (wallboxbilling.class.php, llx_wallbox_sessions SQL, RFID-Hash, Pricing)

**Details:**
- SQLite Session-Manager mit RFID-Autorisierung, Whitelist-Check
- 7-Sekunden Debouncing (HA-07)
- Session start/stop via state transitions (HA-03/04/05)
- Energy calculation: end_energy - start_energy (HA-06)
- Atomare Energie vor Session-Start (PER-05)
- Dolibarr: llx_wallbox_sessions table with all fields (DB-01)
- 4 indexes on rfid_hash, fk_user, start_time, status (DB-02)
- User management with RFID hash(es), price per kWh, cost center
- SQL injection prevention via $db->escape(), (int)/(float) casts (SEC-05)

### Phase 3: API Integration (HA Addon → Dolibarr)

**Goal**: Completed sessions transmitted from HA Addon to Dolibarr via REST API
**Depends on**: Phase 2 (need sessions in SQLite before transmitting)
**Plans**: 2 plans

Plans:
- [x] 03-01-PLAN.md — HA Addon API Client (api_client.py, session_manager, config, main loop)
- [x] 03-02-PLAN.md — Dolibarr Custom API Endpoint (api_wallboxbilling.class.php, DB transmitted_at)

**Details:**
- WallboxApiClient class with DOLAPIKEY auth (API-03)
- Exponential backoff retry: 5 retries, 0.5s factor (API-04)
- JSON payload: rfid_hash, wallbox_id, start_time, end_time, kWh (ISO 8601) (API-02)
- RFID as SHA-256 hash only (API-05)
- Dolibarr: WallboxbillingApi with POST /session, token validation (SEC-03)
- transmitted_at field tracks sync status (D-03)

### Phase 4: Billing + Invoicing + Export

**Goal**: Monthly billing generates invoices and exports for German accounting
**Depends on**: Phase 3 (need sessions in Dolibarr before billing)
**Plans**: 2 plans

Plans:
- [x] 04-01-PLAN.md — Dolibarr Billing Class + Cron Job
- [x] 04-02-PLAN.md — PDF Invoices + CSV/DATEV Export

**Details:**
- WallboxBilling class with runMonthlyBilling() (BIL-01)
- Sessions grouped by user, GROUP BY fk_user (BIL-02)
- Cost = total_kwh × price_per_kwh (BIL-03)
- Cron job registered in modWallboxbilling.class.php
- PDF via TCPDF — detail tables + summary (BIL-04/05/06)
- CSV export via export.class.php (EXT-02)
- DATEV EXTF 5.0 format (EXT-03)

### Phase 5: Hardening + Multi-Wallbox

**Goal**: System survives restarts, supports multiple wallboxes, and handles edge cases
**Depends on**: Phase 4 (core value delivered, now harden)
**Plans**: 2 plans

Plans:
- [x] 05-01-PLAN.md — HA Addon Restart Recovery + WAL Mode
- [x] 05-02-PLAN.md — Multi-Wallbox Support

**Details:**
- SQLite WAL mode: journal_mode=WAL, synchronous=NORMAL, busy_timeout=5000 (PER-04)
- recover_active_sessions() on startup (PER-02)
- mark_session_incomplete() for crash detection (PER-03)
- Multi-wallbox: config.yaml with wallboxes array (id, name, enabled, default) (EXT-01)
- wallbox_id in all session records

## Milestone Summary

**Key Decisions:**
- SQLite für Session-Persistenz (leichtgewichtig, keine externe DB)
- REST-API mit DOLAPIKEY (Standard in Dolibarr, einfach abzusichern)
- RFID-Whitelist per YAML (einfach pflegbar für v1)
- Dolibarr Cronjob für Abrechnung (native Funktion)
- SHA-256 Hash für RFID (kein Klartext, SEC-01/02)
- PDF via TCPDF statt Dolibarr Invoice (optional BIL-07 deferred)

**Issues Resolved:**
- Session-Persistenz über HA-Neustarts (Phase 5 Recovery)
- RFID-Debouncing bei Mehrfachauslösung (Phase 2, 7s)
- API-Retry bei Netzwerkfehlern (Phase 3, Backoff)
- Crash-Erkennung und Session-Bereinigung (Phase 5)

**Issues Deferred:**
- BIL-07: Native Dolibarr Invoice-Erstellung (PDF als primärer Output, optional)

**Technical Debt Incurred:**
- No VERIFICATION.md files for any phase (process gap)
- REQUIREMENTS.md traceability not updated (project management debt)
- PER-04 (WAL mode) not tracked in SUMMARY frontmatter (documentation gap)
