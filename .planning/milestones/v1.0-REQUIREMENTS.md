## Requirements

### HA-Addon Grundfunktionen

- [x] **HA-01**: Home-Assistant-Addon erfasst RFID-Karten über sensor.alfen_eve_tag_socket_1 — ✅ Phase 1
- [x] **HA-02**: Addon prüft erkannte RFID-IDs gegen konfigurierbare Whitelist (YAML) — ✅ Phase 2
- [x] **HA-03**: Ladevorgänge (Sessions) werden mit Startzeit, Endzeit, kWh und Wallbox-ID erfasst — ✅ Phase 2
- [x] **HA-04**: Session-Start erfolgt bei RFID-Erkennung + Whitelist-Validierung + kein aktiver Ladevorgang — ✅ Phase 2
- [x] **HA-05**: Session-Ende erfolgt bei Zustandswechsel auf "Idle" oder "Stopped" — ✅ Phase 2
- [x] **HA-06**: Verbrauchte Energie wird berechnet (End-Energie - Start-Energie) — ✅ Phase 2
- [x] **HA-07**: RFID-Mehrfachauslösungen werden entprellt (7 Sekunden) — ✅ Phase 2

### Persistenz & Stabilität

- [x] **PER-01**: Aktive Sessions werden in SQLite-Datenbank persistiert — ✅ Phase 2
- [x] **PER-02**: Sessions überleben HA-Neustarts (Startup-Recovery) — ✅ Phase 5
- [x] **PER-03**: Unvollständige Sessions werden erkannt und korrekt fortgesetzt/beendet — ✅ Phase 5
- [~] **PER-04**: SQLite verwendet WAL-Modus für bessere Concurrency — ⚠ Phase 5 (implemented, documentation gap)
- [x] **PER-05**: Energie-Zählerstand wird atomar vor Session-Start bestätigt — ✅ Phase 2

### API-Integration (HA → Dolibarr)

- [x] **API-02**: JSON-Payload (rfid_hash, wallbox_id, start_time, end_time, kwh) — ✅ Phase 3
- [x] **API-03**: Absicherung per DOLAPIKEY Token — ✅ Phase 3
- [x] **API-04**: Fehlerhandling mit Retry (exponentieller Backoff) — ✅ Phase 3
- [x] **API-05**: RFID nur als SHA-256 Hash — ✅ Phase 3
